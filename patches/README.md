# patches

Packages that draw their own tool rows have no render hook, so their renderers are patched in place to the Claude Code 2.1.261 look (every row below was measured live with a pywinpty capture of the dark-daltonized theme).

pi-mcp-adapter: a running call is a blinking grey dot + `Calling server…`, a finished call is one grey `Called server` line; consecutive calls to one server merge into Claude's `Called server 3 times` (and join a read-only group: `Read 1 file, called dse 2 times`) through claude-tools' shared grouping on `globalThis.__claudeRows`, earlier rows drawing nothing; ctrl+o expands to `● server - tool (MCP)(args)` + the result rows. An error keeps its row: `● server - tool (MCP)(args)` + red `  ⎿  Error: …` (Claude's error look is unmeasured). The call block never prints in compact mode, so the JSON args dump that used to appear on errors is gone. 2.33.0 added `mcpScript` without a `renderShell`, so pi boxed every call in three rows of `0c0c0c` padding; the patch gives it the same shell as the other MCP tools. A call with no server (`mcpScript`, `mcp` search) joins the group as Claude's catch-all `called N tools` instead of printing its own title row. A failed call inside a group folds into the sentence too (Claude 2.1.280, measured); the error row only shows outside a group or on ctrl+o. A result without `details` (a running `mcpScript`) used to throw inside render and take pi down with an uncaughtException; the compact renderer now reads `details` optionally. Since 2026-09-23 the compact call row draws the whole collapsed group through `__claudeRows.groupRow` (Claude 2.1.280's active group: blinking dot, task summary or `Calling server…`, the `  ⎿  ` hint row; the grey past sentence once the group closes), and the compact result row draws nothing unless ctrl+o expands it, so a call that has not started executing draws nothing at all. Since 2026-09-28 (M5-D) `metadata-cache.ts` drops its tmp file when the rename onto `mcp-cache.json` fails (EPERM when another pi instance replaces it at the same moment) instead of failing MCP init, whose `console.error` shifted the TUI two rows and doubled the startup header. Since 2026-10-05 (M9, `m6e-mcp-panel`, Claude 2.1.289 measured) the `/mcp` panel is Claude's modal pane: `McpPanelView.render` opens with a full-width `99ccff` `▔` rule, `mcp-panel-theme.ts` draws titles, `❯` and the selected name in raw `99ccff` (the theme accent is `87afd7`) and the Capabilities value in raw `ffffff`, `openMcpPanel`/`openMcpAuthPanel` emit `claude-modes:modal` around the panel (a package cannot import an extension file, so the literal event name is used, like `claude-tasks`) and `openMcpPanel` sets `globalThis.__claudeInputPrompted` so the `Try "…"` placeholder does not return after the panel closes. `createMcpPanel` takes `dynamic` (the `--mcp-config` flag is present): the server's path is blanked, which makes the group `Built-in MCPs (always available)` and `Config location: Dynamically configured` as in Claude. The tools screen draws bare names and shows ` · space to toggle direct` in its hint only for a server with direct tools. The connected state of a lazy server is pi's own (`idle` until first use); the parity rig sets `lifecycle: "eager"`.

The `pi` PowerShell wrapper runs `node patches/apply.mjs --if-changed` before every launch and the full `node patches/apply.mjs` after `pi update …`, which does all of the below (skip what is applied, apply what still fits, report `NEEDS PORT` for what does not, run the self-checks). By hand:

Apply (after `pi install` / `pi update`):

    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-mcp-adapter patches/pi-mcp-adapter.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-deepseek-search patches/pi-deepseek-search.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-web-access patches/pi-web-access.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@juicesharp/rpiv-ask-user-question patches/rpiv-ask-user-question.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@tintinweb/pi-subagents patches/pi-subagents.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@dietrichgebert/ponytail patches/ponytail.patch
    node patches/pi-coding-agent.patch.mjs

Verify:

    node patches/pi-mcp-adapter.selftest.ts
    node patches/pi-deepseek-search.selftest.ts
    node patches/pi-web-access.selftest.ts
    node patches/rpiv-ask-user-question.selftest.ts
    node patches/pi-subagents.selftest.ts
    node patches/ponytail.selftest.ts
    node patches/pi-coding-agent.patch.mjs --check

Regenerate a diff patch after editing a package in place: keep a pristine copy of the file (reverse-apply the old patch onto a copy), then `diff -u --label a/<file> --label b/<file> pristine live > patches/<pkg>.patch` (git diff --no-index quotes Windows paths and drops the second file). The pi-coding-agent script asserts each edit matches exactly once, so a pi update that changes the surrounding code fails loudly instead of half-applying.

Self-check: `ponytail.selftest.ts`.
