# patches

Packages that draw their own tool rows have no render hook, so their renderers are patched in place to the Claude Code 2.1.261 look (every row below was measured live with a pywinpty capture of the dark-daltonized theme).

pi-mcp-adapter: a running call is a blinking grey dot + `Calling server…`, a finished call is one grey `Called server` line; consecutive calls to one server merge into Claude's `Called server 3 times` (and join a read-only group: `Read 1 file, called dse 2 times`) through claude-tools' shared grouping on `globalThis.__claudeRows`, earlier rows drawing nothing; ctrl+o expands to `● server - tool (MCP)(args)` + the result rows. An error keeps its row: `● server - tool (MCP)(args)` + red `  ⎿  Error: …` (Claude's error look is unmeasured). The call block never prints in compact mode, so the JSON args dump that used to appear on errors is gone. 2.33.0 added `mcpScript` without a `renderShell`, so pi boxed every call in three rows of `0c0c0c` padding; the patch gives it the same shell as the other MCP tools. A call with no server (`mcpScript`, `mcp` search) joins the group as Claude's catch-all `called N tools` instead of printing its own title row. A failed call inside a group folds into the sentence too (Claude 2.1.280, measured); the error row only shows outside a group or on ctrl+o. A result without `details` (a running `mcpScript`) used to throw inside render and take pi down with an uncaughtException; the compact renderer now reads `details` optionally. Since 2026-09-23 the compact call row draws the whole collapsed group through `__claudeRows.groupRow` (Claude 2.1.280's active group: blinking dot, task summary or `Calling server…`, the `  ⎿  ` hint row; the grey past sentence once the group closes), and the compact result row draws nothing unless ctrl+o expands it, so a call that has not started executing draws nothing at all.

pi-deepseek-search owns the `web_search` tool and renders `web_search "query"` plus a 6-line dump of the answer, inside pi's default tool box. Patched to the Claude Code look (`● Web Search("query")` + `  └ Did 1 search in 12s (3 sources)`), with `renderShell: "self"` to drop the box and `durationMs` in the result details.

pi-web-access owns `fetch_content` and rendered `fetch <url>` / `mode: raw` / a green title with `(962 chars)` and a 200-char preview. Patched to Claude's `● Fetch(url)` (grey dot blinking while it runs, blue once done) + `  ⎿  Fetching…` / `  ⎿  Received 559 chars` (Claude says `559 bytes (200 OK)`; the package has no HTTP status), red `  ⎿  Error: …` on failure, ctrl+o shows the first 20 lines. The finished set is claude-tools' (`globalThis.__claudeRows`).

rpiv-ask-user-question dumped its tool result (`User has answered your questions: "Q"="A" …`) in pi's default box. Patched to Claude's `● User answered Claude's questions:` + one grey `  ⎿  · question → answer` row per answer (`● User declined to answer questions` when cancelled), nothing drawn while the questionnaire is open. Regenerated against 2.10.0 (2026-09-23); the 2.x import block moved, the hunks did not change. Patched again (2026-09-23) for dialog placement and colour parity: the `ctx.ui.custom()` call drops `overlay`/`overlayOptions`/`onHandle` so the dialog sits in the normal editor slot (claude-bottom-input then pads it to one row under the transcript, same as the permission dialog) instead of an overlay anchored to the bottom of the screen; `collapseKey` is forced to `"off"`, which also drops the `Ctrl+]` hint from the footer since the overlay-only collapse/hide feature has no effect without an overlay. `wrapping-select.ts` paints the pointer and the `N.` number separately from the label (accent pointer + muted number, only the label turns accent when selected) instead of one uniform coloured line, and mutes the "Type something." row even at rest. `build-questionnaire.ts` supplies those two new theme colours as raw `#99ccff` (no matching theme role, same reasoning as `claude-modes`' `MODE_LINE`). `tab-content-strategy.ts` gives the header chip a `☐` glyph on a `#99ccff` background with black text (was `selectedBg` with no glyph), the question text moves to column 0 in `text` role white, and the footer hint drops `n to add notes` (no such feature in Claude's dialog) and renders in `muted` at column 0 instead of `dim` at column 1. `dialog-builder.ts`'s top/bottom rule uses `muted` instead of `accent`, and drops the `Spacer(1)` between the top rule and the header chip (Claude's chip sits directly under the rule; `topFixed` in `DialogView.render` drops the matching `+ 1` so the overflow/scroll math stays consistent). The chip `Text` also drops its own `paddingX` (was `1`) since the coloured chip string already opens with its own space — Claude's own colour run is `[fg=000000,bg=99ccff] ☐ Colour ` starting at column 0, not an extra uncoloured margin before a colour run that itself starts with a space. `answeredRows()`'s `"● "` before both "User answered…" and "User declined…" is now `"● "` (a non-breaking space, matching a live Claude capture byte-for-byte; a plain space measured one character short). Since 2026-09-23 the dialog also has Claude 2.1.280's `N. Chat about this` row (last item of the same numbered list, under a muted rule, accent `99ccff` when focused; choosing it declines in the transcript and tells the model the user wants to talk first), the multi-question tabs and `Review your answers` / `Ready to submit your answers?` step, multiSelect `[ ]`/`[✔]` rows, the `ctrl+g to edit in <editor>` hint once focus has reached the free-text row (sticky, as in Claude's `po` state), and the decline row's per-question `· question (opt1 / opt2)` summary. The result row reads the model's raw `questions` argument, so a question without `options` is skipped rather than crashing render (it took pi down once in the suite). `User answered Claude's questions:` is default foreground, not the `toolTitle` role. Patched again (2026-09-24) for Claude 2.1.280's question auto-continue and schema rejection: `questionnaire-session.ts` runs Claude's AFK clock (`afkStep`, one tick a second, idle = now − max(last key, start), a focused terminal restarts it, the external editor being open resets it instead of firing) and draws the always-present bottom row with the right-aligned countdown; the reducer's `afk_timeout` action submits the picks so far (a checked but unconfirmed box counts) with `afkTimeoutMs`; the envelope sends Claude's AFK text; `answeredRows` draws `● Claude asked:` … `● No response after Ns — …`; `renderResult` turns a pi schema failure (`Validation failed for tool`) into `⎿ Invalid tool parameters`. The timeout comes from `askUserQuestionTimeout` in `~/.claude/settings.json` or `CLAUDE_AFK_TIMEOUT_MS`/`CLAUDE_AFK_COUNTDOWN_MS`, and the tool turns on terminal focus reporting (`?1004h`, off again at exit) at the first agent turn when it is set, reading focus events through `onTerminalInput` without consuming them (pi-tui ignores them in regular mode and handles them itself in fullscreen). Self-check: `rpiv-ask-user-question.selftest.ts`.

pi-coding-agent itself (minified bundle, so a script instead of a diff, applied to every installed copy: Roaming npm and Volta): a hidden thinking block draws nothing, so tool rows sit one blank line apart instead of three; an interrupted reply ends with grey `  ⎿  Interrupted · What should Claude do instead?` instead of red `Operation aborted`. The tool-side half of the interrupt (an aborted tool result) is handled by claude-tools / intent-tools, and claude-working prints no `✻ … · done` line after an interrupt. `PI_SKIP_VERSION_CHECK` (the `pi` wrapper sets it) also skips the "Package Updates Available" box, which pi gates on `PI_OFFLINE` only; that box is also the one that talks you into `pi update --extensions`, which wipes every patch here. A status notice (`MCP: 1 servers connected`, `Model: x`) draws as Claude's grey `● notice` at column 0 instead of a dim line one column in. pi 0.85.1 renamed `message2` to `message` in the stop-reason branch; the script was ported on 2026-09-23 and asserts every anchor, so the next rename fails loudly again. Since then the script has grown to one numbered entry per Claude rule in its header (23 on 2026-09-23): markdown (headings without `#`, h1 italic, 2-column list nesting, `▎` quotes with a dim bar, literal thematic breaks, GFM table alignment, fence-less code blocks, SGR 94 links), the 3-line Update-diff context, the slash menu's layout, Ink's `trim:false` word wrap (a row after an exactly-full row holds one column less), the widget spacer that would otherwise sit between the transcript and a dialog, and the `/clear` built-in. Two edits only open a door for an extension: the slash menu asks `globalThis.__claudeSlashMatch` (`extensions/claude-slash-menu`, Claude's own Fuse.js 7.0.0 matcher and ranking) before pi's fuzzy filter, and a code fence asks `globalThis.__claudeFenceHighlight` (`extensions/claude-tools/markdown-highlight.ts`, Claude's ANSI-16 code-fence colouring on highlight.js 11.12) before pi's own highlighter. `node patches/pi-coding-agent.patch.mjs --check` lists every edit; applied to a pristine 0.85.1 bundle the script reproduces the installed one byte for byte.

pi-subagents loads `src/index.ts` (its `pi.extensions` entry), not `dist/`, so the patch is on the source. The Agent tool drew `▸ Agent  desc` inside pi's default box, which put two or three blank padding rows between consecutive agents, and a backgrounded one said `⎿  Running in background (ID: …)`. Patched to Claude Code 2.1.280 (measured): `● Agent(desc)` with the blue tool dot and no box, `  ⎿  Backgrounded agent (↓ to manage · ctrl+o to expand)` (↓ at an empty prompt really does open pi-subagents' fleet list), and the finished-agent notification collapsed to `● Agent "desc" finished · 50s` (ctrl+o keeps the stats and preview; a failed agent keeps its old block, Claude's is unmeasured). SubagentWorkflow gets `renderShell: "self"` for the same padding reason. `get_subagent_result` has no renderer of its own; claude-tools' fallback now takes over any tool whose definition has no renderCall/renderResult (pi 0.85.1 counts a bare definition as "has renderer"), so it folds into the group instead of dumping the agent's whole report. The manager registry it exposes at `Symbol.for("pi-subagents:manager")` also carries `backgroundRunningCount()` (top-level, `isBackground`, `running`/`queued` records) so `claude-working` can print Claude's `✻ Waiting for N background agent(s) to finish` instead of the done line while one is still going; the registry also carries `fleetLines(width, theme)` and `fleetHint(theme)`, which `claude-footer` draws under its mode row. `src/ui/fleet-list.ts` is patched to Claude 2.1.280's agents list (bundle `xW`/`p4`/`f4`/`k4`, measured live): a blank row, bold `  ● main`, then one `  ◯ <subagent_type>  <description>  <elapsed>[ · ↓|↑ N tokens]` row per agent, all 999999, name column padded to the longest name (4–28), status right-aligned two columns in, five rows windowed with `↑/↓ N more`; running and queued agents from spawn, background ones that failed or were stopped for 30s with a red `◯`, completed ones never (the mode row's `/tasks to see subagents` takes over); elapsed is Claude's `Gt`, tokens its `Ts` (last input + cache + all output). Its own below-editor widget renders nothing now and only keeps the TUI handle for the 1s tick. ↓ at an empty prompt selects `❯ ● main` and the mode row becomes `↑/↓ to select` (Claude 2.1.281; 2.1.280 added ` · Enter to view`); on an agent `Enter to view · x to stop` (`x to clear` once it ended); `x` stops or clears, ↑ past main or Esc leaves. Self-check: `pi-subagents.selftest.ts`.

The `pi` PowerShell wrapper runs `node patches/apply.mjs --if-changed` before every launch and the full `node patches/apply.mjs` after `pi update …`, which does all of the below (skip what is applied, apply what still fits, report `NEEDS PORT` for what does not, run the self-checks). By hand:

Apply (after `pi install` / `pi update`):

    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-mcp-adapter patches/pi-mcp-adapter.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-deepseek-search patches/pi-deepseek-search.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/pi-web-access patches/pi-web-access.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@juicesharp/rpiv-ask-user-question patches/rpiv-ask-user-question.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@tintinweb/pi-subagents patches/pi-subagents.patch
    git -c core.autocrlf=false apply --directory=npm/node_modules/@dietrichgebert/ponytail patches/ponytail.patch
    node patches/pi-coding-agent.patch.mjs

Verify:

    node patches/pi-mcp-adapter.selftest.ts
    node patches/pi-deepseek-search.selftest.ts
    node patches/pi-web-access.selftest.ts
    node patches/rpiv-ask-user-question.selftest.ts
    node patches/pi-subagents.selftest.ts
    node patches/ponytail.selftest.ts
    node patches/pi-coding-agent.patch.mjs --check

Regenerate a diff patch after editing a package in place: keep a pristine copy of the file (reverse-apply the old patch onto a copy), then `diff -u --label a/<file> --label b/<file> pristine live > patches/<pkg>.patch` (git diff --no-index quotes Windows paths and drops the second file). The pi-coding-agent script asserts each edit matches exactly once, so a pi update that changes the surrounding code fails loudly instead of half-applying.

ponytail prints `Ponytail loaded: <mode>` on every session start. `/new` and `/clear` start a session too, and Claude prints nothing after `/clear`, so the patch skips the notice when the session starts with reason `new`. Self-check: `ponytail.selftest.ts`.

Note: pi-web-access also registers a `web_search` tool (rendered as `search "query"`). It loses the name to pi-deepseek-search, which registers on `session_start`, after every extension has loaded. Nothing renders that one, so it is left unpatched.
